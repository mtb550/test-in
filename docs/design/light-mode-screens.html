Every state of the standalone always-on-top window, drawn at its real size. This page is the pictures only — what each part is, why it is that way, and every decision behind it are in the design document, which is the one place the reasoning is written. Two pages so that neither repeats the other and neither can quietly stop agreeing with it.

Where it opens from

One new button on the run editor toolbar, beside the execution controls it belongs with. Its icon is a sun, AllIcons.MeetNewUi.LightTheme — it names the mode rather than the gesture. The design asked for a window holding a smaller window in its corner and no stock icon draws that: General.OpenInToolWindow points its arrow into the frame rather than out of it, and General.ExpandComponent ships at half opacity, so it would have looked permanently disabled beside the buttons it sits with. Borrowed rather than drawn, which is what “Four plugin logos and no action icons: a Testin icon set for menus, nodes and toolbars” tracks. It is a toggle: press to open light mode, press again to close it and carry on in the editor, and it stays pressed for as long as the window is there. It is enabled only while the run is open, and greys out the moment the run reaches Completed or Closed — the same question that disables Start, and the same one that closes the window if it is open.

Pressing F

Passed and Blocked are one keystroke — recorded, and on to the next case. Failed is the one verdict that asks for something back, because a failure nobody described is a failure nobody can act on.

P — Passed

Recorded. Advances immediately. There is nothing to say about a case that worked.

B — Blocked

Recorded. Advances immediately — why a case was blocked belongs in Result Analysis, on the run.

F — Failed

The window becomes the capture below. Enter saves and advances; Escape returns the case unjudged.
